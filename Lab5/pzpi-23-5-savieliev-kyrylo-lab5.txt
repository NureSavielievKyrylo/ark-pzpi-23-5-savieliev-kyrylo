3 ОПИС ВИКОНАНОЇ РОБОТИ
Під час виконання лабораторної роботи було створено програмні засоби для
розгортання програмної системи на машинах з операційною системою macOS або
Linux.
На початку був зібраний Docker образ для серверної частини програмної
системи, та опублікований у моєму публічному Docker Hub репозиторії.
Після чого було розпочато роботу над bash скриптом для автоматизації
розгортання програмної системи з автоматичним налаштуванням необхідних
параметрів та втановленням залежностей.
Під час розробки скрипту однією з основних задач було реалізувати безпечне
введення паролів та секретів без їх відображення у терміналі. Для цього було
розроблено функцію read_password, що зчитує пароль із прихованим введенням,
яке реалізовано завдяки опції -s команди read:
read_password() {
local prompt="$1"
local default="$2"
local value
if [ -n "$default" ]; then
read -sp "$(echo -e ${YELLOW}${prompt}${NC} [auto-generated]: )"
value
echo "" >&2
echo "${value:-$default}"
else
read -sp "$(echo -e ${YELLOW}${prompt}${NC}: )" value
echo "" >&2
echo "$value"
fi
}

Для читання даних із значеннями за замовчуванням використовується
функція read_with_default, що зчитує введене значення або повертає значення за
замовчуванням, якщо користувач не ввів нічого:
read_with_default() {
local prompt="$1"
local default="$2"
local value
if [ -n "$default" ]; then
read -p "$(echo -e ${YELLOW}${prompt}${NC} [${default}]: )" value
echo "${value:-$default}"
else
read -p "$(echo -e ${YELLOW}${prompt}${NC}: )" value

echo "$value"
fi
}

Однією з основних вимог до програмного засобу для розгортання було
забезпечення запуску на декількох платформах (macOS та Linux). Для цього було
реалізовано перевірку операційної системи за допомогою змінної оточення OSTYPE,
що дозволяє коректно виконувати команди залежно від платформи:
detect_os() {
if [[ "$OSTYPE" == "linux-gnu"* ]]; then
if [ -f /etc/os-release ]; then
. /etc/os-release
echo "$ID"
else
echo "unknown"
fi
elif [[ "$OSTYPE" == "darwin"* ]]; then
echo "macos"
else
echo "unknown"
fi
}

Також немало важливою була візуальна привабливість скрипту, для цього
було реалізовано кольорове форматування виводу за допомогою ANSI escape
послідовнестей для задання кольорів та використання еможди для покращення
сприйняття інформації.
Розроблений скрипт працює наступним чином:
–

Перевірка наявності Docker на машині користувача, у разі відсутності
- виводиться відповідне повідомлення про автоматичнк встановлення
Docker на машину користувача;

–

Конфігурація зовнішнього порту для доступу до серверної частини
програмної системи (за замовчуванням використовується порт 8080);

–

Конфігурація списку дозволених адрес для підключення до серверної
частини програмної системи (CORS);

–

Конфігурація СУБД PostgreSQL: задання імені користувача, назви БД
та паролю, якщо пароль не задано, генерується випадковий пароль за
допомогою утиліти openssl rand;

–

Конфігурація БД Redis: задання імені користувача та паролю, якщо пароль
не задано, генерується випадковий пароль за допомогою утиліти openssl
rand;

–

Конфігурація AWS S3 сховища: задання імені бакету, регіону, access key
та secret key;

–

Генерація секретів для авторизації та куків;

–

Створення .env файлу з усіма необхідними змінними оточення для роботи
серверної частини програмної системи;

–

Створення продакшн Docker Compose файлу для розгортання серверної
частини програмної системи разом із СУБД PostgreSQL та Redis;

–

Запуск Docker контейнерів за згодою користувача за допомогою Docker
Compose;

–

Вивід інформації про успішне розгортання програмної системи.

Аби запустити скрипт достатньо виконати низку команд у терміналі:

install.sh
chmod +x install.sh
./install.sh

Після чого скрипт проведе користувача через усі етапи налаштування та
розгортання програмної системи.
